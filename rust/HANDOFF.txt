CONFIRMED FINDINGS / IMPLEMENTED REPAIRS
======================================
- The old Rust activation path required BOTH a Raw Input-maintained Hold flag
  and GetAsyncKeyState's current down state. A controlled test reproduced zero
  outputs in both modes when Windows reported Hold down but that raw flag was
  absent. A GPU-only test matched a real desktop pixel, so that reproduction
  localized a real blocker to activation rather than proving the shader broken.
- Current code uses one shared key-edge handler for Raw Input and asynchronous
  fallback. It includes release/configuration guards, suppression during capture
  and dialogs, and a release-before-reactivation guard after edits.
- Ordinary Settings interactions could leave processing suspended. Suspension
  was restricted to actual editing/capture/picker/modal/picking interactions.
  Minimise/navigation should not leave a permanent disabled latch. Audit this.
- Capture/initialization errors used to be silently discarded. Current code
  records error transitions to engine.log and uses Disabled rather than falsely
  implying initialization succeeded. GPU resources initialize in the worker.
- The previous fullscreen calibration overlay filled its colour-key background,
  then Canvas::new cleared the whole graphics surface to OPAQUE near-black.
  Mouse movement invalidated that fullscreen surface. That was a concrete black-
  flash-producing code path. The replacement is a small persistent alpha marker;
  no fullscreen Canvas clear or fullscreen invalidation remains in that path.
  This was source-inspected, NOT visually verified as flicker-free on the user's PC.
- Screen picking now hides the entire main/settings surface and colour popup.
  Temporary mouse/Escape callbacks are installed only for selection and cleaned
  up on completion/cancel. The eyedropper uses the existing worker's DXGI pixel
  readback, not a second duplicator. Preview is offset from the sampled pixel.
- RGB tolerance was already present in the shader; the repaired Settings UI
  exposes it in the spare space beside the unbind hint. Both modes share it.
